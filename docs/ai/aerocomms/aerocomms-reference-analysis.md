# AeroComms Landing — Reference Analysis

## Purpose

This document analyzes the visual and structural direction of the reference landing page provided by the user.
The goal is not to copy the original website, but to extract reusable design principles and adapt them into an original AeroComms landing page inside FlyPath.

AeroComms should feel premium, clean, modern, aviation-focused and clearly part of the FlyPath ecosystem.

---

# 1. General Direction

The reference landing has a modern SaaS/editorial feel:

- Large typography.
- Very clean layout.
- Strong black/white contrast.
- Generous white space.
- Minimal but premium visual language.
- Floating app mockups.
- Soft shadows.
- Rounded cards.
- Smooth motion.
- Mobile-first composition.
- Simple but confident product storytelling.

For AeroComms, use this same level of visual polish, but adapt it to FlyPath’s identity and aviation training positioning.

The final result should not feel like a cloned website. It should feel like:

> AeroComms by FlyPath — a premium ATC communications training experience for future pilots.

---

# 2. What to Take as Inspiration

Use the reference for these design principles:

## Layout

- Sticky/fixed header.
- Hero section with a very strong headline.
- Clear CTA near the top.
- Large product mockup below or beside the hero.
- Section-by-section storytelling.
- Alternating text and visual blocks.
- Feature grids.
- App screenshots/cards arranged in floating compositions.
- FAQ near the end.
- Final CTA section.

## Visual Style

- Large, confident headlines.
- Short supporting paragraphs.
- Minimal distractions.
- Rounded cards.
- Light shadows.
- Clean spacing.
- Premium SaaS look.
- Editorial typography touches, such as selective italic words.
- Mostly white/light background, with dark text.
- Optional dark premium sections if aligned with FlyPath.

## Motion

- Subtle fade-in on scroll.
- Slight slide-up animation for cards.
- Floating mockups.
- Light parallax on hero visuals.
- Sticky visual sections where appropriate.
- Smooth hover effects on cards/buttons.
- No heavy animations that hurt mobile performance.

## Content Rhythm

The page should feel like a guided product story:

1. What AeroComms is.
2. Who it is for.
3. What problem it solves.
4. How the training works.
5. What modules exist.
6. How progress/feedback works.
7. How the user can join or try it.

---

Do not copy any of the following from the reference:

- Logo.
- Brand name.
- Exact copy.
- Exact section text.
- Exact app screenshots.
- Exact icons.
- Exact illustrations.
- Exact testimonials.
- Exact pricing.
- Exact layout measurements.
- Exact animation timings.

- User numbers or social proof claims.

The landing must be original and adapted to FlyPath/AeroComms.

# 6. Visual Direction for FlyPath Adaptation

The visual style should combine:

- Reference landing polish.
- FlyPath educational trust.
- Aviation training seriousness.
- Modern product feel.

Recommended design direction:

- Mostly light background.
- Dark navy/black text.
- FlyPath accent color for CTAs.
- Premium rounded cards.
- Mockups with subtle depth.
- Slight aviation/radar/cockpit details, but not too much.
- Avoid making it look like a gaming product.
- Avoid excessive neon/cyberpunk styling.

---

# 7. Motion Direction

Use motion only to enhance clarity.

Recommended:

- Fade/slide section entrance.
- Hero mockup floating slowly.
- Cards entering with stagger.
- Very light parallax on mockup group.
- Smooth hover effects.
- Sticky visual block in one section maximum.

Avoid:

- Too many animations.
- Fast movement.
- Heavy video backgrounds.
- Scroll hijacking.
- Complex 3D unless already supported.
- Anything that hurts mobile performance.

---

# 8. Copywriting Rules

Language:

- Spanish by default.
- English only for aviation examples.

Tone:

- Clear.
- Direct.
- Premium.
- Realistic.
- Educational.
- No hype.
- No fake urgency.

Avoid:

- “Domina la radio en 7 días”
- “Habla como un piloto profesional desde cero”
- “IA revolucionaria”
- “Miles de pilotos ya lo usan”
- “La app definitiva”

Prefer:

- “Entrena paso a paso”
- “Gana confianza”
- “Practica antes de la radio real”
- “Mejora listening y readbacks”
- “Progresión guiada”

# 9. Technical Implementation Notes

When implementing in Cursor:

1. Inspect current FlyPath project structure first.
2. Reuse existing layout, header, footer and button styles where possible.
3. Create the route `/aerocomms`.
4. Build the static layout first.

7. Use placeholders for app screenshots if real assets are not ready.

10. Do not modify unrelated pages.
